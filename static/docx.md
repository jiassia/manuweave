# Word 规则排版

通过 `scripts/manuweave.py` 调用本地工具，用户无需掌握命令。原稿与参考文档始终保留，成果写入新路径。

有参考 Word 时，`learn-style` 从已识别角色提取实际生效格式，考虑继承、直接覆盖、中英文字体及多个同角色实例，保存来源位置。检查提取结果是否包含目标所需的标题、作者、单位、摘要、关键词、各级标题、正文、公式、图表、题注、参考文献、页眉页脚和纸张分栏规则。未识别角色不会自动形成可靠规则，不能把字段枚举当成已完成提取。当前 `learn-style` 不接受参考角色覆盖；作者、单位等缺失时，依据参考稿实际位置补充有证据的 JSON 规则，再应用该配置。参考内容不进入目标稿件。

使用内置配置时，通过 `presets list/show/catalog` 读取 JSON。先核对 `rules`、`page` 与 `extracted_format`，再将真实块 ID 映射到对应角色。双语标题、作者、单位、摘要、关键词和图表题注分别匹配；段内字体变化和首段等例外保留条件。

执行字体字号、字形、对齐、缩进、段距、固定或最小行距等明确规则。页面规则包含纸张、边距、页眉页脚距离、分栏和栏距；有前置单栏与正文双栏要求时，按标明的正文起点设置分节。数学、表格、图片和题注采用各自规则，不将正文固定行距机械套在纯图段上。

引擎在副本中精确修改 OOXML，保留 OMML、原始媒体、关系、合并单元格、书签、字段、脚注和注释部件。禁止复制原模板对象或重建全文。角色歧义通过 `inspect` 的真实位置和 `plan --roles` 解决。

自动角色仅作建议。作者、单位及双语块需要宿主依据内容核对；`run` 使用自动角色，修正映射需使用 `plan --roles` 后 `apply`，后续 `audit --roles` 和 `render --profile PROFILE --roles ROLES` 传入相同映射。参考稿含多个分节时，提取结果仅以最后一节提供页面默认值并给出警告，不能自动还原所有分节。按明确要求另行设置受支持的前置单栏和正文双栏边界。

段内保留目前覆盖相对继承段落基准的混合粗体、斜体，包括字符样式继承。长强调占多数时，现有主格式检查可能与角色基准冲突，保留强调并报告格式失败，不通过删除强调满足规则。全段粗斜体一致时，引擎无法区分强调与段落直接格式，仍按角色规则替换。字体、字号和颜色仍按角色规则统一设置，不能承诺保留全部段内例外。先检查这些差异是否承载内容含义；存在未支持且必须保留的例外时，在修改前说明范围并保留原稿。原生对象保持检查比较内容和关系，不能代替对象的逐页显示检查。

执行后比较原文和对象清单，通过现有 Word 或 LibreOffice 生成页面。查看公式、题注、表格、图片、标题换页、页眉页脚和实际字体，局部修复后复查。两篇稿件不必拥有相同页数。

`check_fonts` 只检查字体族是否安装。自动 PDF 字体检查仅抽查正文中唯一文本样本的少量中英文字形，未覆盖全部字符、标题、题注和页眉页脚。`english-single` 的中英字体均设为 Times New Roman，中英混排需选择合适配置或明确字体偏差；中文回退为宋体仍属与该配置不符，不能忽略失败。末页较空需区分内容长度、明确换页和版式缺陷，不以压缩规定行距、边距消除空白。
